# Спільні фікстури «Наші V2»

У `fixtures/` зберігаються готові статичні відповіді для дизайн-студії й моків вебзастосунку. Сервер має віддавати цю теку за шляхом `/fixtures/`. Генератор використовує вбудовані модулі Node.js 24. Початкові дані потрібні лише для повторної генерації.

## Походження даних

Джерело знімка — `nashi-backend/build/wiki-dry-run.json` від 8 листопада 2026 року. SHA-256 файла — `68f50c1f05d271c9c808b8c940e4084bf29e0e393eb90737983e92f36279880a`. У знімку 14 881 запис, зокрема 4 349 категорії MUSICIAN або BAND. У 683 музикантів відсутнє місце, для п’ятьох зазначене місце проживання і для трьох — місце роботи. Карту побудовано з 3 658 записів із відомими регіоном, координатами та місцем народження або заснування. До цієї вибірки додано три вигадані демонстраційні заявки з `scripts/fixture-extras.json`.

| Вміст | Кількість |
| --- | ---: |
| Піни | 3 661 |
| Унікальні населені пункти | 1 112 |
| Області, АР Крим і міста зі спеціальним статусом | 27 |
| Повні профілі | 86 |
| Фрагменти з доступним локальним WAV | 548 |

У `profile-slugs.json` перелічено доступні повні профілі. До вибірки входять усі 20 записів першої сторінки каталогу і всі три демонстраційні заявки. Наприклад, `musicians/okean-elzy.json` містить місце заснування у Львові, джерело тексту і фото з кредитом Alexander Khanin під CC BY-SA 4.0. `musicians/oksana-lyniv.json` містить місце народження у Бродах і кредит Mykola Swarnyk. `map-pins.json` і `map-places.json` охоплюють весь набір.

Тексти Вікіпедії мають посилання на статтю та CC BY-SA 4.0 у `textSource`. Генератор прибирає артефакти дат і скорочує вступ; повний оригінал доступний за посиланням. У `images[].credit` збережено автора, ліцензію і сторінку файла Wikimedia Commons. З 1 357 фотографій у відібраних записах 29 мали неповні відомості про автора, тому для них відображається ініціал. За зовнішніми посиланнями завантажуються оригінальні мініатюри V1. Авторські ілюстрації демонстраційних заявок містяться у `img/`.

Шість WAV-файлів — згенеровані синусоїдальні мелодії тривалістю 15 с (моно, 22 050 Гц, PCM 16 біт). Для 546 виконавців наявність музичного або відеопосилання в V1 дає можливість випробувати аудіоплеєр. Для двох демонстраційних заявок аудіо ввімкнено у вхідних даних. Кожен фрагмент має джерело UPLOAD і підпис про синтетичний звук студії. Лічильники уподобань детерміновано змодельовані, а `updatedAt` відповідає часові знімка. Тип населеного пункту наближений за правилами S2. Сортування підказок спирається на кількість музикантів. Координати пінів відхилені від центру за формулою §4 спільного контракту.

## Повторна генерація та перевірка

З кореня репозиторію після `npm ci`:

```sh
npm run build:fixtures -w contracts -- --dry-run /path/to/nashi-backend/build/wiki-dry-run.json
npm test -w contracts
```

За замовчуванням використовуються збережені `geo/regions-meta.json` і вихідна тека `fixtures/`. Параметри `--regions-meta` і `--out` дозволяють перевірити інший знімок в окремій теці. Тести зіставляють агрегати з усіма пінами, перевіряють профілі, атрибуцію, діапазони фрагментів та структуру WAV. Якщо створено `openapi.yaml`, відповідні файли також проходять перевірку за його схемами.

`map-pins.json` займає 1 351 350 байтів, або 304 680 байтів після gzip. Розмір включає повні Unicode-імена, стабільні slug та ID, координати, регіони і наявні URL мініатюр. Навіть компактний JSON без усіх мініатюр і з координатами до шести десяткових знаків для цього знімка займає 733 129 байтів. Орієнтир 600 КБ для нестисненого файла у плані S2 потребує зміни формату або бюджету.
